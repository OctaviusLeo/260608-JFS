System Architecture

👤 User Browser
↓ visits S3 URL
☁️ AWS S3 — Angular App
us-east-1 · todo-app-storage-jam98
↓ /api/* requests proxied by Nginx
🖥️ AWS EC2 — Spring Boot (Docker)
us-east-2 · todo-app-spring-server · :8080
↓ reads/writes
🗄️ SQLite — todo.db
persisted via Docker volume mount

Key Design Decisions

  • S3 and EC2 are in different regions — this is intentional and works fine over the internet
  • Nginx proxies /api calls so the browser only talks to one origin
  • SQLite writes to a host volume so the database survives container restarts
  • JWT is stateless — no session storage on the server

The CI/CD Pipeline

Every push to main automatically triggers Jenkins to run through all four stages.

① Checkout
Pull latest code from GitHub
② Build
Gradle bootJar + Docker image build
③ Test
REST Assured + Cucumber E2E — pipeline stops if anything fails
④ Deploy
Push Docker image to EC2, sync Angular build to S3

Slide 09

Testing Strategy

REST Assured — API Layer

  • Tests every endpoint directly over HTTP
  • Verifies correct status codes (201, 200, 404, 401)
  • Validates response body structure
  • Runs against H2 in-memory DB during CI

Cucumber + Selenium — E2E Layer

  • Tests full user flows in a real browser (headless Chrome)
  • Covers: register → login → create task → complete task → delete
  • Written in plain English feature files anyone can read
  • Catches integration issues the API tests cannot see

Together these two suites give us confidence at the contract level and the user experience level. If both pass, the app is working correctly end to end.

Slide 10

Technical Deep Dive

Why structure the pipeline as Checkout → Build → Test → Deploy?
Each stage depends on the one before it. We fail fast — if the build breaks we skip the test run entirely. No wasted time or broken deployments.
How did Docker help the pipeline?
The same Docker image runs in Jenkins and on EC2. There is no environment mismatch between CI and production. If it passes in Jenkins it will behave the same on AWS.
How do S3 and EC2 work together?
S3 serves the static Angular files. The Nginx config inside the frontend container proxies any /api request to the EC2 backend. The browser only ever talks to one origin so there are no CORS issues.
Slide 11

What We Learned

  • Automated testing changed how we write code. Knowing every push runs the full suite made us more careful about what we committed.
  • The biggest challenge was getting Docker, Jenkins, and AWS all talking to each other — especially the networking between the Nginx proxy and the backend service name.
  • Docker made the "it works on my machine" problem disappear. Once the image was built it behaved the same everywhere.
  • Moving from manual deployment to a single git push felt like a significant shift in how software delivery works.
